# Fast judgments, deeper help — full film

Audience: engineers building judgment-driven applications. About 7 minutes.
One worked ticket example. Other domains are independent reuse cues.

Question: how do we turn repeated judgments into completed work, while keeping
deeper investigation available without making it the driver of every decision?

Arc: start with the developer's problem; develop human recognition and deliberate
thinking as an analogy; map it to typed AI judgments; expose the machinery needed
around them; introduce Pi and Turbo; work through a ticket; reveal responsibilities,
native integration seams, and finally small author functions.

The central visual payoff is an evidence packet returning to the same System One
driver. Tool execution and its actual result are distinct from the model's judgment.

## Grammar and production

Dark background, original vector drawings, Avenir Next text, 1920×1080 at 30fps.
Cyan: System One; amber: System Two; blue: developer's facts/policy;
purple: Turbo; green: Pi. Names and legends appear only when introduced.
No taxonomy or code in the opening. Small pseudocode appears after the architecture.
All routes and probabilities are illustrative; no live cost/latency/accuracy claim.
Durability means recorded sessions/control and author-retained business evidence here;
automatic crash replay is not demonstrated or promised. No overflow edge cases.

Use Manim Community Cairo consistently. Preserve objects where facts change;
send visible packets when information changes hands. Pause for diagrams/code.
Narration: downloaded Kokoro 82M 8-bit, af_heart, local MLX, speed 1.0.
Measure each paragraph before fixing durations. Final chapter times follow generated
audio, not the old storyboard's edit budget. Render/review a draft before final output.
